### 字句解析器の残タスク(code-review 2026-08-15の指摘含む)

- 改行はNewlineトークン化済み(2026-08-15。複数行ソースが読める)。CRLFは受理・単独CRはE0117で**決定・実装済み**(ADR-0041、仕様L-29)。`;`→E0110、非ASCII識別子→E0103 は引き続き暫定E0116(src/lexer.rsのErrorCode docに一覧)。文終端の挿入(L-19/L-20/L-21)は**字句側**の後続サイクルで実装する(ADR-0010のGo方式・ADR-0031の深度スタック。実装がA-9の実証を兼ねる)。**制約: 直前がNewlineの改行には終端を挿入しない**(コメントのみの行・空行は裸のNewlineが並ぶため、空文を作らない。L-4のID `comment-before-continuation` のテスト化もこのサイクル)
- float(L-10/L-13)・指数部、16進等の基数接頭辞(L-9の `0x_FF`、check_digit_separatorsの基数別digit対応)、L-11整数範囲(E0107)、L-12(E0113。`1_x` はE0105優先=仕様L-9注2で確定済み)
- **演算子・記号列は実装済み**(2026-08-16: 1.9の全演算子=1文字13種(`=` 含む)+2文字13種。最長一致(L-2)は「2文字表 `two_char_operator_kind` を先に引き、外れたら1文字表」の順序で実現。L-3の `0..10` 分割は数値分岐無変更で成立——**float側の境界(`1.5..2` 等)はfloatサイクルで追加検証**。`===`・`->` はE0116を複数文字spanで報告(負例ID triple-equals 回収。案内文言はエラーメッセージ層の担当)。`/` 分岐は非消費先読み化し単独 `/` は除算Slash。backtick-string / single-quote-string も後追い網で回収。非消費先読みは `peek_at` 部品に集約)。**CRLF分岐はマッチャに寄せない決定**: CRLFは1.9でなくL-29(ADR-0041)の担当で、単独CR=E0117のエラー意味論は `Option<TokenKind>` 返しの演算子表では表現できないため、専用分岐を維持する
- コメント・文字列基礎・**補間も実装済み**(2026-08-15: L-17の再帰トークン化と種類照合つき括弧対応=ADR-0042の入れ子方式、L-18/E0109(不均衡含む)、L-17(b)/E0115、**L-31のネスト上限64段/E0118**=スタック保護。優先順位はL-18注1・注2で明文化。字句はnext_token/scan_string/scan_interpolationに構造化)。**予約語テーブルも実装済み**(2026-08-15: 完全予約語22語=Kw*トークン、誘導用22語=字句段階で即E0104、文脈キーワード=Ident維持(L-27)、interpolation-nested 3例目も回収)。**パーサ着手時に実装するE0104**: L-8(`or error =>` の専用案内)に加え、完全予約語が識別子位置に現れた場合の本体(`let let = 1` 等。6章H-2 error-as-value・H-4 error-type-declの変種を含む)——字句はKw*トークンを渡すだけで、識別子位置の判定はパーサの担当。残: 行継続(L-19〜L-25)・数値の残り(float・基数・L-11・L-12)
- エラーメッセージ層: ErrorCode→文言+修正候補の対応表とDisplay実装(testing-strategy原則2のスナップショット対象)。「字句エラーは1件で止めるか全件集めるか」はパーサ着手前にADR化。E0112は3原因(形式/範囲/サロゲート)が同一コードのため、メッセージ実装時に原因タグの導入を検討。E0104も同様(誘導用の語別案内4種+L-8変種+6章H-2/H-4変種。語はspanの再スライスで取得可)
- **BOM(U+FEFF)のファイル先頭の扱いが仕様未定義**(現状E0116で不可解なエラーになる。実ファイルを読ませる前=CLI整備までに決定する。小決定、CRLFと同様にADR化)
- 設計メモ: scan_whileの引数契約を型で守る(Lexer struct化の候補)/ EOFの空span表現 / Token.textの&str化検討 / `lex_ok`テストヘルパー(全正例テストで `text == source[span]` 不変条件を自動検査。文字列リテラル等の正規化トークン導入時に必須)/ 行頭オフセットは `Newline.span.end` から求める(`span.start + 1` はCRLF行で1バイトずれる=A-18関連)/ **fmt・LSP(Phase 8)はコメントの保持が必須**——現在コメントは痕跡なく破棄されるため、triviaチャネル(トークンに付随情報として残す方式)か再字句解析が必要になる / 文字列内CRLFのE0108 spanは `\r` 1バイトのみを指す(不可視文字。エラー描画層の設計時に粒度を再検討)/ `\u{` の16進桁収集は拒否パスで無制限にStringへ蓄積する(実害小・上限つきカウンタ化の候補)/ ネストしたStrのtext保持はO(深さ²)のメモリ増幅(L-31の64段上限で実用上抑止済み。根本策はToken.textのSpan導出化=&str化と同件)
