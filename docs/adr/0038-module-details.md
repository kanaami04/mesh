# ADR-0038: モジュールの詳細(トップレベルはletのみ・定数式初期化・as別名・リーク禁止・ルートimport不可)

- **Status**: accepted
- **Date**: 2026-08-14
- **決定者**: ユーザー + Claude(仕様7章の執筆時に確定。1はユーザー確認済み、2〜4は既定原則からの導出、5・6はspec-reviewの指摘を受けた確定)

## Context

仕様7章の執筆でモジュールレベルの未決事項を確定した(ADR-0017の詳細化)。

## Decision

1. **トップレベルは `let`(不変)のみ。`mut` は禁止**。グローバル可変状態を言語から排除し、共有状態は「main内のmut+クロージャ捕捉」(ADR-0036)に集約する。
2. **import別名 `as`** を置く(`import "ui/json" as ujson`)。同名パッケージの衝突時に回避手段が無いと詰むため(構文追加の判定基準「無いと解決不能」に該当)。既定の参照名はパスの最終セグメント。
3. **export宣言のシグネチャに非export型を使うのはエラー**(APIから辿れない型が漏れるのを防ぐ。AIが公開APIだけ読んで使える状態を保つ)。
4. **未使用importはエラー**(ADR-0035の未使用変数と同系。書き忘れ・消し忘れの網)。
5. **トップレベルletの初期化式は定数式に限る**(リテラル・演算子・補間・struct/listリテラル・他のトップレベルlet参照・無名fn式。**関数呼び出しは不可**)。理由は3つ: ①`let counter = makeCounter()` の形でmut捕捉クロージャがグローバル可変状態として復活する抜け道を封じる(spec-reviewの指摘)。②副作用が無いため初期化順が観測不能になり、順序の仕様(パッケージ依存順・ファイル名順の決定性)が丸ごと不要になる。③初期化中のpanic・async初期化の問題が構造的に消える。let間の参照は非循環であること(コンパイラが依存順に評価)。
6. **サブパッケージからルートパッケージはimportできない**(依存は上→下の一方向。ルートは参照名を持たず、ディレクトリ名の識別子制約からも自由になる)。

## 検討した代替案と捨てた理由

- **トップレベルmut許可**: TS/JSの手癖に合うが「どこから書き換えられたか分からない」グローバル変数バグを輸入する。前実装が「main内mut+捕捉」で足りることを実証済み。
- **as無し(衝突は常にエラー)**: `std/json` と自作 `json` の共存が不可能になる。
- **非export型のリーク許容(Go方式)**: 使う側が名前を書けない型が公開APIに現れ、AIにも人間にも扱えない値が生まれる。
- **トップレベルletの初期化式に関数呼び出しを許可(Go方式)**: クロージャ抜け道に加え、初期化順の決定性(トポロジカル順のタイブレーク・ファイル名照合順)とpanic・top-level awaitの仕様が必要になり複雑化する。動的な初期値はmainで組み立てる。

## 既存ADRとの相互作用

- ADR-0017: パッケージ=ディレクトリ・常に修飾・循環禁止の詳細化。エイリアス検討の宿題を決着。
- ADR-0036(参照捕捉): 決定1により共有状態の経路がクロージャ捕捉に一本化される。
- ADR-0008(不変デフォルト)/ ADR-0035(未使用エラー): 同じ設計思想の適用。

## Consequences

- 仕様7章に規範として明文化する。4章S-6の対象からトップレベルletを除外する(公開定数のため)。
