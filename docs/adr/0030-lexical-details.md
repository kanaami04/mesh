# ADR-0030: 字句の詳細(識別子ASCII・数値リテラルはフルセット・文字列は単一行)

- **Status**: accepted
- **Date**: 2026-08-14
- **決定者**: ユーザー + Claude(仕様1章の執筆時に確定)

## Context

仕様1章の執筆で字句レベルの未決事項が3つ見つかり、ユーザーと確定した。

## Decision

1. **識別子はASCIIのみ**(`[a-zA-Z_][a-zA-Z0-9_]*`)。文字列・コメントの日本語は制限しない。
2. **数値リテラルはフルセット**: 10進・桁区切り `_`・指数表記・`0x`/`0b`/`0o`(JS/Go/Rustと同等)。
3. **文字列リテラルはv1では単一行のみ**(改行は `\n`)。複数行リテラルは需要が出たら将来追加。

## 検討した代替案と捨てた理由

- **Unicode識別子**: 日本語話者には直感的だが、見た目が同じ別文字の混入バグ・正規化・lintの複雑化を抱える。
- **数値の縮小セット(16進なし等)**: 仕様は小さくなるが、主要言語すべてが持つ共通装備でありAIの学習データとも一致するため、削る利得が小さい。
- **複数行文字列**: 主用途(UI内テキスト)はview構文側で自然に書けるため優先度が低い。後から足しても互換。

## 既存ADRとの相互作用

- ADR-0014(コードポイント単位): 識別子のASCII制限は文字列の内容には及ばない(文字列はUnicode全域)。
- ADR-0015(int 53bit): 整数リテラルの安全域超過は字句・構文段階の静的エラーにする(仕様1章 L-11)。
- ADR-0019(範囲 `0..n`): floatの「小数点両側に数字必須」規則(仕様1章 L-10)とセットで字句衝突を解消。
