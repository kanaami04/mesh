# ADR-0005: 不在と失敗はunion型で表す(`T | none` / `T | error`)

- **Status**: accepted(規則5は0028、規則7は0037で精密化)
- **Date**: 2026-08-13
- **決定者**: ユーザー + Claude

## Context

Phase 1の根幹決定(値の不在とエラー処理の方式)。ユーザーの明示要望により、前プロジェクトMesh(`~/kanaami/mesh`)の意味論棚卸し文書(semantics.md)から「不在と失敗」の設計を選択的に引き継ぐ。この設計はMeshの14の意味論軸のうち、3目標(FE/BE両対応・人が読みやすい・AIが書きやすい)すべてに◎が付いた唯一の軸であり、「言語の背骨。触ってはいけない」と実証済みの評価を得ていた。

## Decision

不在は `T | none`、失敗は `T | error` のunion型で表す。**汎用のnull・undefined・例外(try/catch)・多値戻りは言語に置かない。**

意味論の要素(記号の見た目はラウンド2以降で確定。ここで決めるのは仕組み):

1. **narrowing**: `is` による型の絞り込み。**絞り込む前に中身へ触るとコンパイルエラー**(未処理の不在・失敗を機械的に弾く)。
2. **match網羅性検査**: unionの全メンバーを処理しないとコンパイルエラー。
3. **伝播 `?`**: `v := f()?` — none/errorなら呼び出し元へ即return。戻り値型に失敗メンバーが無い関数内で使うとコンパイルエラー。
4. **文脈付き伝播 `? "文脈"`**: 失敗時だけ文脈を評価して `error("文脈: 元メッセージ")` に包んで伝播。noneもerrorに昇格するので不在に理由を付けられる。
5. **フォールバック `or`**: 素の `or 式` は**none専用**。errorを含むunionには束縛形(`or e => 式` / `or _ => 式`)を必須にし、エラーの黙殺を構文レベルで防ぐ。右辺は失敗時のみ評価。
6. **`== none` の禁止**: narrowingが効く `is none` に一本化(書き方を1つに保つ)。
7. **構造化エラー**: `error struct` / `error type` の前置マーカーで宣言した型は、組み込みerrorと同じく `?`/`or` の伝播対象になる。「どのメンバーが失敗か」を位置ではなく宣言側の明示マーカーで決める。
8. **JS境界での正規化**: FFIから入るnull/undefinedは `none` に、例外は `T | error` に変換する。JSの2空値問題を言語内に輸入しない。

## 検討した代替案と捨てた理由

- **nullable修飾子 `T?`**(Kotlin/Swift風): union型と別の仕組みが言語に2つ共存し、仕様が増える。
- **Option/Result型**(Rust風): `Some(x)` の包み剥がしが冗長。unionなら包まず直接値を扱える。
- **例外(try/catch)**: どの関数が失敗しうるかが型に現れず、処理忘れが実行時まで発覚しない。

## Assumptions

- A-7: unionメンバーを実行時に区別する仕組み(型タグ)をJS出力で低コストに実現できる。**前実装ではここが未設計のまま実装され、名前付きstruct同士のunionをmatch/isで分岐すると実行結果が静かに誤るバグが残っていた**(意味論の棚卸し文書 軸6の実測)。本プロジェクトは最初から実行時タグをコード生成の設計に含める。

## Consequences

- 言語の他の部分もこの語彙に揃える(例: mapの読み取りは `V | none` を返す、テストの合否表現)。新しい概念を増やす前に「none/errorで表せないか」を先に検討する。
- 網羅性検査とnarrowingが型検査器の中核実装になる(Phase 3の主工数。ここがMeshの価値の本体)。
- エラーメッセージ仕様(style-guide原則4)は「絞り込み前アクセス」「網羅漏れ」「or束縛忘れ」の3種を最優先で磨く。
