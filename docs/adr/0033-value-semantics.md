# ADR-0033: 複合値(struct・list・map)は値意味論、等価は値の比較

- **Status**: accepted
- **Date**: 2026-08-14
- **決定者**: ユーザー + Claude(仕様3章の執筆時に確定。structの決定をユーザーと確定後、spec-reviewの指摘を受けてlist/mapへの拡張・等価の推移性・再帰struct等価の禁止を追加し、**2026-08-14にユーザーが明示的に追認**)

## Context

複合値(struct・list・map)の代入・引数渡しの意味論と、等価比較 `==` の適用範囲を決める必要があった。言語の性格を決める最大級の決定。

## Decision

1. **struct・list・mapのすべての複合値は値意味論**: 代入・引数渡し・returnで独立した値になる。別名経由の書き換え(`mut b = a; b.age = 31` で `a` が変わる、`push(b, x)` が `a` に及ぶ)は**起きない**。(listを参照のまま残すと「別名書き換えの排除」が半分になるため、複合値全体で統一する。仕様3章レビューで確定)
2. コピーの実装は「変更が観測できる場合のみコピーする」最適化を許す(意味論はコピー、実装は自由)。
3. **等価 `==` はプリミティブ・none・struct(フィールドの深い値比較)・それらのunion値に適用できる**。`== none` は禁止のまま(`is none` へ誘導。ADR-0005)。
4. **list・mapの `==` はコンパイルエラー**(O(n)の深い比較が無自覚に書かれる事故を防ぐ。要素比較は標準関数で明示。Goと同じ割り切り)。fn値の `==` もエラー。
5. **等価可能性はフィールドを推移的に検査する**: list/map/fn/js.Valueをフィールドに(推移的に)含むstruct、および**フィールドを辿って再帰的に自身へ到達するstruct**(`Node { next: Node | none }` 等)の `==` もエラー(深い比較の内側で禁止したはずのO(n)比較が静かに発生するのを防ぐ。比較したいフィールドの直接比較を案内)。

## 検討した代替案と捨てた理由

- **参照意味論(JSそのまま)**: 実行コストゼロでTSの手癖と一致するが、「純粋に見える関数が呼び出し元のデータを静かに書き換える」というJS/TS最大級のバグ類型を言語ごと輸入する。「読んだとおりに動く」の看板と両立しない。
- **struct == もエラー**: 最小だがUser同士の比較のたびに関数が要り日常が冗長。
- **list/mapも深い比較**: 一貫するが、大きなlistの `==` がループ内で静かにO(n)になる罠。

## Assumptions

- A-15: 値意味論のコピーコストが「観測可能時のみコピー」最適化でWebアプリ用途の実用域に収まる(前実装は同方針。「引数が不変なら引数渡しのコピーは観測不能=除去可能」の分析済み)。**list/mapへの拡張によりこの前提の重要度が上がった**(大きなlistのコピー頻度がベンチマーク必須項目)。

## 既存ADRとの相互作用

- ADR-0008(不変デフォルト): 不変束縛+値意味論で「一つの名前=一つの値」が完成する。可変(mut)の変更もその名前の値だけに閉じる。
- ADR-0005: 等価の適用範囲はunion値にも及ぶ(実行時タグで判別してメンバー同士を比較)。
- ADR-0022(FFI): JSへ渡す境界では参照が渡りうる(JS側の変更はMeshの意味論の外。10章で規定)。
- ADR-0003(UI): 宣言的UI(state更新→再描画)は値の木と好相性(前実装の棚卸しでも「宣言的UIなら味方」と分析済み)。

## Consequences

- 仕様3章(等価・式の評価)と4章(代入)に規範として明文化する。
- コード生成は変更検出とコピー挿入の分析を持つ(Phase 2〜3。A-15の検証対象)。
- クロージャによる捕捉の意味論(値意味論下で唯一の共有経路になりうる)は5章で定める。
