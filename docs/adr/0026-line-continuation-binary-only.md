# ADR-0026: 行継続は二項演算子に限定(後置 `?` は文を終端できる)

- **Status**: accepted(ADR-0010の継続規則の精密化。改行区切り自体は変更なし)
- **Date**: 2026-08-14
- **決定者**: ユーザー + Claude(設計監査 2026-08-14 の発見#2)

## Context

ADR-0010は継続規則を「行末が演算子・カンマ・開き括弧なら継続」と書いた。設計監査で、後置演算子 `?`(ADR-0005)がこの規則を誘発する欠陥が見つかった:

```
let user = findUser(id)?
"保存しました"              // 継続扱いだと findUser(id)? "保存しました"
                            // = 文脈付き伝播として合法にパースされ、意味が静かに変わる
```

エラーにならず意味が変わる、この言語の設計目標に対する最悪クラスの罠。

## Decision

- 行継続が起きるのは、行末トークンが**二項演算子**(`+ - * / == && ||` など。確定一覧は仕様1章)・カンマ・開き括弧(`( [ {`)・`=`・`=>` の場合のみ。
- **後置 `?` は文を終端できる**(継続を誘発しない)。
- 帰結として、文脈付き伝播 `? "文脈"` は `?` と同一行に書くことが必須になる。

## 検討した代替案と捨てた理由

- **`?` も継続扱いのまま**: 上記の静かな誤りを許すため不可。
- **`? "文脈"` を別記号にする**: 記号を増やすより行規則で解決する方が仕様が小さい。

## Assumptions

- A-9(継続規則を単純に定義しきれる)を「後置演算子の除外リストが必要」と修正して維持。

## Consequences

- 仕様1章の継続規則に「二項/後置の区別」の明文と、この負例をconformanceテストとして必ず載せる。
- 同型の罠(新しい後置記法を足したとき)を防ぐため、後置演算子の追加時は継続規則への影響確認を必須とする。
