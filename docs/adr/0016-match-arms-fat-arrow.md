# ADR-0016: matchの腕は `=>` で区切る(ブレース形を撤回)

- **Status**: superseded by ADR-0025(`=>` は維持、本体を「常にブロック」に変更)
- **Date**: 2026-08-13
- **決定者**: ユーザー + Claude

## Context

ADR-0013でブレース形(区切り記号なし)を採用したが、直後にユーザーの実読テストで「自分が決めた記法なのに、パッと見て理解に1ステップ入る」ことが判明した。ブレース形は「コードは波括弧」の規則一貫性は最高だが、**パターンと結果の間に視覚的な区切りが無く、どこまでがパターンかを目が探す**コストがあった。規則の一貫性より読み取りの速さを優先して差し替える。

## Decision

腕は `パターン => 式またはブロック` で書く。

```
match findUser(id) {
  User u => u.greet()
  none   => "未登録"
}
```

関数の `->` を廃止済み(ADR-0011)のため、`=>` は**Musubiで「matchの腕」だけに現れる専用記号**となり、「記号1つ=意味1つ」が保たれる。

## 検討した代替案と捨てた理由

- **ブレース形(ADR-0013)**: 上記のとおり実読で区切りの視認性に難があった。
- **`->`**: 関数で廃止した記号のmatch限定復活になり、一貫性がない。
- **`:`**: コロン多用の視覚的負担が戻り、型注釈のコロンと意味が被る。

## Assumptions

- (特になし。`=>` はAI学習データ最多の記法であり、A-10のような検証前提が不要になる)

## Consequences

- ADR-0013はsuperseded。前提A-10(ブレース形とAIの相性)は前提ごと消滅。
- 短い腕は1行で書ける(`none => "未登録"`)。結果が複数文ならブロック `=> { ... }`。
- fmtは腕の `=>` の位置を揃える(視認性をさらに上げる)。
