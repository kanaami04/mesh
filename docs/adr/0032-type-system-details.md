# ADR-0032: 型の詳細(list/map記法・type透過・文字列添字・範囲外panic)

- **Status**: accepted
- **Date**: 2026-08-14
- **決定者**: ユーザー + Claude(仕様2章の執筆時に確定)

## Context

仕様2章の執筆で型レベルの未決事項が4つ見つかり、ユーザーと確定した。

## Decision

1. **コレクション型は `list<T>` / `map<K, V>`**。`T[]` 短縮形は置かない(型構成子の記法をジェネリクスの1形に統一)。
2. **`type` エイリアスは透過的な別名**。`type Shape = Circle | Square` はインラインの union 式と完全に同じ型。新しい名目型が欲しい場合は struct で包む。
3. **文字列の添字 `s[i]` は string(1コードポイント)を返す**。char型は置かない。
4. **list・string の範囲外アクセスは panic**(位置つき即時エラー。ADR-0027の境界で回復)。mapの `m[k]` は `V | none` のまま(**不在はデータ、範囲外はバグ**という区別)。

仕様2章の敵対的レビュー(spec-review)で追加確定した3点:

5. **型引数は不変(invariant)**: `list<int>` は `list<int | none>` に代入できない(可変コレクションの健全性。Goと同じ割り切り。TSの非健全な共変は採らない)。
6. **mapのキー型は `int` / `string` / `bool` に限定**(値の等値が自明なプリミティブのみ。floatはNaNの等値問題で除外。structキーは参照等値の罠になるため不可)。
7. **型式中のfn型の戻り型は右方最長**(`fn(int) int | none` は union を返すfn。関数宣言の読みと一致)。fn型をunionメンバーにするときは括弧。

## 検討した代替案と捨てた理由

- **`T[]` 短縮形**: TSの手癖には合うが、mapに同種の短縮が無く2記法が混在する。
- **typeを新名目型に**: named unionとインラインunionが別型になり、関数境界で意図しない不一致が頻発する。
- **char型新設**: 厳密だが型と変換関数が増え、シンプルさ方針と合わない。
- **範囲外で `T | none`**: 常に安全だが全添字アクセスに絞り込みが必要になり日常コードが冗長化する。

## 既存ADRとの相互作用

- ADR-0005: mapの読み取り `V | none` は維持(本ADRの区別の「不在はデータ」側)。
- ADR-0014: `s[i]` の単位はコードポイント(1文字=1コードポイントのstring)。
- ADR-0020: `list<T>`/`map<K,V>` は通常のジェネリック型として扱われ、特別規則を持たない。
- ADR-0027: 範囲外panicは境界回復の対象。

## Consequences

- 仕様2章(docs/spec/02-types.md)に規範として明文化する。
- panicする操作の一覧は仕様6章(エラー処理)に集約する。
