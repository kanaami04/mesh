# ADR-0014: 文字列の長さ・添字はコードポイント単位

- **Status**: accepted
- **Date**: 2026-08-13
- **決定者**: ユーザー + Claude

## Context

Phase 1ラウンド3のQ11。前プロジェクトでは文字列の単位を「一度も決めておらず」、JSのUTF-16がそのまま漏れて `len("👍")` が2を返し静かに壊れる穴が指摘されていた(semantics.md 軸13)。決めないこと自体が仕様の穴になる領域。

## Decision

`len(s)`・添字・スライスは**Unicodeコードポイント単位**とする。

```
len("あいう")  // 3
len("👍")      // 1(UTF-16では2だが、コードポイントでは1)
```

書記素クラスタ(👨‍👩‍👧のような合成絵文字)は複数コードポイントのままとし、必要になったら将来 `graphemes(s)` を標準ライブラリに追加する(lenの意味は変えない)。

## 検討した代替案と捨てた理由

- **UTF-16コードユニット(JSそのまま)**: 実行コストゼロだが、絵文字・一部の漢字で数え違いが静かに起きる。前実装で指摘された穴そのもの。
- **書記素クラスタ単位(Swift流)**: 人間の直感に最も近いが、Unicodeのセグメンテーション実装が必要でコストが大きい。
- **lenを置かず単位別関数のみ**: 誤解は無いが日常操作が冗長。

## Assumptions

- A-11: コードポイント単位の実行コスト(UTF-16との変換)がWebアプリ用途で実用域に収まる。

## Consequences

- コード生成は `[...s]` / `String.prototype.codePointAt` 系の変換を挟む。`len` はO(n)になりうる(必要ならランタイムでキャッシュ)。
- 言語カードに「lenはコードポイント数(絵文字の合成は複数)」を明記する。
- JS FFI境界では単位の混同が起きないようAPI設計時に単位を明示する。
