# ADR-0035: 文の詳細(パラメータ不変・効果なし式文はエラー・未使用変数はエラー・deferなし)

- **Status**: accepted
- **Date**: 2026-08-14
- **決定者**: ユーザー + Claude(仕様4章の執筆時に確定。1・2はユーザー確認済み、3・4は既定原則からの導出)

## Context

仕様4章の執筆で文レベルの未決事項を確定した。

## Decision

1. **関数パラメータは常に不変**(`mut` パラメータは無い)。書き換えたい場合は `mut local = param` と明示的にコピーする。
2. **効果のない式文はエラー**(Go方式)。`x + 1` 単独の行は代入・return忘れの兆候であり機械的に弾く。
3. **未使用のローカル変数はエラー**(Go方式)。意図的な破棄は `let _ = f()` で明示する。
4. **defer文はv1に置かない**。リソース解放の定型はまず標準ライブラリの高階関数(コールバック形)で受け、構文が必要だと実証されたら新ADRで導入する。

## 検討した代替案と捨てた理由

- **mutパラメータ許可**: 局所的に便利だが、値意味論(ADR-0033)との組み合わせで成立する「関数は渡された値を一切変更できない」という強い性質と、それに基づくコピー省略最適化(A-15の根拠)が弱まる。
- **効果なし式文・未使用変数の許可**: 自由度はあるが書き忘れバグが静かに通る。AIの書き損じを弾く網としての価値が大きい。
- **defer採用**: 前実装には存在したが、v1のスコープを絞る。「後から足せる」方向の限定。

## 既存ADRとの相互作用

- ADR-0033(値意味論)+本決定1: 「関数は引数を変更できない」が成立し、引数渡しのコピーは観測不能=除去可能(A-15)。
- ADR-0008(let/mut): パラメータはlet相当の扱いに統一される。
- ADR-0027(panic境界): deferが無いため「panicしても必ず実行される後処理」は書けない。境界回復側(ランタイム)の責任とする。

## Consequences

- 仕様4章に規範として明文化する。
- 1章の誘導用予約語に `defer` を追加する(誤用時に案内)。
