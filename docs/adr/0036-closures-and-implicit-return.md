# ADR-0036: クロージャはmut変数を参照捕捉・関数は暗黙のreturn

- **Status**: accepted
- **Date**: 2026-08-14
- **決定者**: ユーザー + Claude(仕様5章の執筆時に確定。B案の影響範囲・「ブロック=値」廃止の帰結を検討した上での選択)

## Context

仕様5章の執筆で2つの根幹決定が必要になった: ①値意味論の言語でクロージャが外側のmut変数をどう捕まえるか。②関数本体の最終式を戻り値とするか(暗黙のreturn)、return必須とするか。

## Decision

1. **クロージャによるmut変数の捕捉は参照(共有)**: クロージャ経由の変更は外側に見え、外側の変更もクロージャに見える。これは値意味論(ADR-0033)の言語で共有状態(カウンタ・キャッシュ・アプリ状態)を持てる**唯一の意図的な経路**である。let変数の捕捉は不変のため値と参照が観測上区別できない(実装自由)。
2. **暗黙のreturnを採用**: 関数本体の最終式が戻り値(Rust流)。「波括弧ブロックの最後の式が値」の規則(if式・match腕・or束縛で確定済み)を関数本体にも通し、全域1本にする。途中脱出は従来どおり `return`。

## 検討した代替案と捨てた理由

- **捕捉時コピー**: 理論上純粋だが、共有状態を書く手段が言語から消える(カウンタすら書けない)。
- **return必須(Go流)**: 出口の明示性とTS手癖への一致という利点はあるが、「ブロック=値」規則が関数本体だけ例外になり規則が2本になる。なお「ブロック=値」の全域廃止はif式(0009)・match腕(0025)・or束縛(0028)の3決定を連鎖的に崩すため選択肢に無いことを確認した。

## Assumptions

- A-16: 参照捕捉のJS実装(クロージャ変数をそのままJSクロージャで共有)が値意味論の他の部分と干渉しない(捕捉されたmut変数への代入は「その変数」の更新であり、値のコピー規則X-1と両立する)。机上では自明だがコード生成で確認する。

## 既存ADRとの相互作用

- ADR-0033(値意味論): 捕捉共有は「別名書き換えの排除」の意図的な例外。ただしクロージャの型 `fn() int` がシグネチャに現れるため、隠れた別名にはならない。
- ADR-0025/0009/0028: 「ブロック=値」が全域1本になり、これらの規則と完全に一貫する。
- ADR-0008(不変デフォルト): 共有できるのはmutだけ。letの捕捉に共有の概念は生じない。

## Consequences

- 仕様5章に規範として明文化する。makeCounter(クロージャカウンタ)がconformanceテストの代表例になる。
- コード生成はmut捕捉変数をJSクロージャ変数として共有する(コピー最適化の対象外)。
