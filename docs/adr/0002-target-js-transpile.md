# ADR-0002: コンパイルターゲットはJavaScript(トランスパイル方式)

- **Status**: accepted
- **Date**: 2026-08-13
- **決定者**: ユーザー + Claude

## Context

絶対軸「FE+BE両対応」の実現手段として、実行方式を決める必要があった。業界の先行例はJS路線(TS, Gleam, Topcoat)とWASM路線(MoonBit, Rust+wasm)に大別される。

## Decision

**JavaScriptソースへのトランスパイル**を唯一の初期ターゲットにする。FEはブラウザ、BEはNode/Bunで実行。ソースマップを出力しデバッグ体験を確保する。

## 検討した代替案と捨てた理由

- **WASMターゲット**: 性能・サイズは優るが、DOM操作にJSグルー層が必須でFE実装量が激増する。GC設計も必要。Tokioチーム製Topcoat(2026-07)ですらブラウザ側は「Rust式→JS変換」を選んだことが、JS路線の妥当性を裏付ける。
- **段階的ハイブリッド(最初からJSとwasmの両方に対応できるIR=中間表現を設計する案)**: 将来性はあるが初期速度を犠牲にする。コード生成層を差し替え可能な構造にするだけに留め、wasmは将来のADRで再検討する。
- **自前VM/ネイティブ**: ブラウザで動かずFE軸と矛盾。

## Assumptions

- A-1: JS出力の実行性能が対象用途(Webアプリ)で実用域に収まる。
- A-2: ソースマップで十分なデバッグ体験を提供できる。
- A-4: JSのGC・ランタイムへの相乗りで、自前ランタイムを最小限にできる。

## Consequences

- GC・機械語生成・JITを作らなくてよい(実装量の大幅削減)。
- npmエコシステムをFFI経由で利用可能。
- 実行性能の上限はJSエンジンに律速される(non-goalなので許容)。
- コード生成層はAST直結にせず、将来のwasmバックエンド追加を阻害しない構造にする。
