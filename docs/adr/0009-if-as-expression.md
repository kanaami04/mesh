# ADR-0009: `if` は式(分岐はすべて値を返せる)

- **Status**: accepted
- **Date**: 2026-08-13
- **決定者**: ユーザー + Claude

## Context

Phase 1ラウンド2のQ6。前プロジェクトの意味論棚卸しで「`match` は式なのに `if` は文」という非対称が実測され、「同じ分岐概念に書き方が2種類あり、AIが `if` を式として書いて落ちる」緊張が指摘されていた。

## Decision

`if`/`else` を **式**にする。`match` と揃え、「分岐は値を返せる」に統一する。

```
let label = if count > 0 { "あり" } else { "なし" }
```

値として使う場合は `else` 必須(全経路が値を持つことをコンパイラが検査)。文の位置に置けば従来どおり副作用目的でも書ける。

## 検討した代替案と捨てた理由

- **ifは文のまま**: 単純だが「値が欲しい分岐はmatch、副作用はif」という使い分け規則を人とAIが覚える必要が残る。
- **三項演算子 `a ? b : c` の追加**: if式があれば不要。`?` は伝播演算子(ADR-0005)と衝突するため採用しない。

## Assumptions

- (特になし。Rust/Kotlinで実証済み)

## Consequences

- 三項演算子は言語に存在しない(書き方を1つに保つ)。
- JSコード生成では式のifを即時関数か一時変数に変換する(コード生成の設計事項)。
