# ADR-0017: パッケージ=ディレクトリ、使用時は常に修飾

- **Status**: accepted
- **Date**: 2026-08-14
- **決定者**: ユーザー + Claude

## Context

Phase 1ラウンド4のQ13。コードの分割単位(モジュール)とimportの形を決める必要があった。

## Decision

- パッケージ=ディレクトリ。`package` 宣言は書かない(ディレクトリ名がパッケージ名)。
- `export` を付けたトップレベル宣言だけが外から見える。
- 使用時は常に `パッケージ名.シンボル` で修飾する(`json.parse(body)`)。裸のnamed importは無い。
- **ネストパスを最初から許す**(`import "ui/components"`)。前実装ではv1非対応で、FE/BE同居リポジトリで痛むと診断されていた穴。
- 循環importはコンパイルエラー。importに副作用は無い。
- 標準ライブラリの名前空間は予約する(例: `std/...`。詳細は仕様7章)。

## 検討した代替案と捨てた理由

- **TS流(ファイル=モジュール+named import)**: AI学習データ最多だが、シンボルの出所を追うにはimport文へ戻る必要があり、同名衝突のrename管理も発生する。局所性の方針と合わない。
- **ハイブリッド(選択importも許す)**: 書き方が2つになる。

## Assumptions

- (特になし。Goで長期実証済みの方式+ネスト対応)

## Consequences

- どの識別子も出所が字面で一意に分かる(AIはファイル単体を読むだけで解決できる)。
- パッケージ名の衝突回避(同名ディレクトリのimport)は仕様7章でエイリアス構文を検討する。
