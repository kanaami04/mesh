# ADR-0003: UIは言語組み込み構文にする

- **Status**: accepted
- **Date**: 2026-08-13
- **決定者**: ユーザー + Claude

## Context

「Reactのいいとこ取り」をどう具体化するか。UI記述を言語仕様に含めるか、ライブラリに置くか、既存Reactへバインドするかの選択。

## Decision

**JSX風のUI記述構文(component / state / view)を言語仕様そのものに組み込む**。リアクティビティ(state更新→再描画)も言語/標準ライブラリレベルで提供する。

## 検討した代替案と捨てた理由

- **標準ライブラリとしてのUI**: 言語コアは汎用に保てるが、「オールインワン言語」の理想から遠ざかる。UI構文をパーサ・型検査に統合できる強み(例: `<button onClick={...}>` の属性に型検査が効く)を捨てることになる。
- **既存Reactへのバインド**: 実装は最速だがReactへの依存が言語の寿命を縛る。プロトタイプ検証用としては将来も選択肢に残す。

## Assumptions

- A-5: JSX風構文はMusubiの文法と衝突せずパース可能(例:「`<` が比較演算子かタグの開始か」の曖昧さは、viewブロック内限定の構文にすることで回避できる)。
- A-6: リアクティビティの実現方式(仮想DOM or fine-grained)は Phase 6 で決められる(今決めなくてよい)。

## Consequences

- 言語仕様にUI章(spec 9章)が必要になり、仕様量が増える。
- Dart/Flutter同様、言語とUIフレームワークを共進化させられる。
- パーサはHTML風タグを扱うため通常の式パーサより複雑になる。
