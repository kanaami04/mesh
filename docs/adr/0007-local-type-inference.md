# ADR-0007: 型注釈は局所推論(関数境界は必須、ローカルは省略可)

- **Status**: accepted(無名関数の注釈は0029で精密化)
- **Date**: 2026-08-13
- **決定者**: ユーザー + Claude

## Context

Phase 1ラウンド1のQ4。型注釈をどこまで書かせるか(=型推論をどこまで効かせるか)を決める必要があった。

## Decision

**局所推論**を採る。関数の引数と戻り値の型は必ず書く。ローカル変数の型は初期化式から推論して省略できる。

## 検討した代替案と捨てた理由

- **完全推論(OCaml/Haskell流)**: 記述量は最小だが、型エラーが発生源から離れた場所で報告されやすく、エラー品質最優先の方針(vision)と相性が悪い。
- **全注釈必須**: 最も明示的だが、自明な型(`let sum = 0`)まで書かせるのは冗長で、シンプルさの方針と合わない。

## Assumptions

- (特になし。TS/Go/Rustで実証済みの方式)

## Consequences

- 関数シグネチャが常に明示されるため、関数単位で読み書きが完結する(AIの局所性)。ADR-0005の「シグネチャを見れば失敗が全部分かる」も常に成立する。
- 型エラーの報告位置が関数内に局在する。
- 型検査器はHindley-Milner級の全域推論が不要になり、実装が単純になる(初期実装コストの削減)。
