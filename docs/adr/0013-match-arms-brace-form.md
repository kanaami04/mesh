# ADR-0013: matchの腕はブレース形(区切り記号なし)

- **Status**: superseded by ADR-0016(実読テストで区切りの視認性に難があり、`=>` へ変更)
- **Date**: 2026-08-13
- **決定者**: ユーザー + Claude

## Context

Phase 1ラウンド3のQ10。関数のアロー廃止(ADR-0011)に伴い、例で使っていたmatchの腕の `->` も見直す必要があった。

## Decision

腕は「パターン+波括弧ブロック」で書く。区切り記号は無し。

```
match findUser(id) {
  User u { greet(u) }
  none   { "未登録" }
}
```

「コードのかたまりは常に波括弧」という規則1本で、if・fn・matchすべてが同じ形になる。

## 検討した代替案と捨てた理由

- **`=>`(Rust/JS流)**: AIの学習データでは最多だが、アロー記号が言語に戻ってくる。
- **`->` 維持**: 関数で廃止した記号をmatchだけに残すのは一貫性がない。

## Assumptions

- A-10: ブレース形の腕(学習データでは少数派)がAIの生成成功率を大きく損なわない。

## Consequences

- 短い腕でも波括弧が付く(fmtが1行形 `none { "未登録" }` を許すかは仕様6章の詳細で決める)。
- パーサは「パターンの終わり=`{` の出現」で判定でき、区切り記号の解析が不要になる。
