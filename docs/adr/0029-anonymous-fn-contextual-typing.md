# ADR-0029: 無名関数は文脈的型付けで注釈省略可

- **Status**: accepted
- **Date**: 2026-08-14
- **決定者**: ユーザー + Claude(設計監査 2026-08-14 の発見#5の決着)

## Context

ADR-0007(関数の引数・戻り値の注釈は必須)を無名関数に厳密適用すると、`http.serve(3000, fn(req) { ... })` のようなコールバックが書けず、毎回完全な関数型を書く摩擦が大きい。specのスケッチとも矛盾していた(監査で検出)。

## Decision

- **期待型が確定している位置**の無名関数は、引数・戻り値の型注釈を省略できる(文脈的型付け。TSと同じ挙動):
  - 関数型が宣言されている引数位置(`http.serve(3000, fn(req) { ... })`)
  - 関数型の注釈が付いたlet(`let f: fn(int) int = fn(x) { x + 1 }`)
- 期待型が無い位置ではADR-0007どおり注釈必須(`let f = fn(x) { x + 1 }` はエラー。メッセージで注釈追加を誘導)。
- 名前付き関数(トップレベル・レシーバ付き)の注釈必須は**不変**。

## 検討した代替案と捨てた理由

- **無名関数も常に注釈必須**: 規則は1本だがコールバック多用のFE/BEコードで摩擦が大きすぎる。
- **無名関数は常に省略可**: 期待型が無い場所では推論できず、エラー品質が落ちる。

## Assumptions

- (特になし。TSで実証済みの双方向型検査の局所適用)

## 既存ADRとの相互作用

- ADR-0007(局所推論): 「注釈必須」の対象を名前付き関数に限定する精密化。局所性は保たれる(無名関数の型は同じ式の中の期待型から決まる)。
- ADR-0021(色なしasync): 無名関数も非同期性推論の対象。externの同期コールバック位置に非同期到達の関数値を渡すとエラー(監査#9の規則)。
- ADR-0022(FFI): extern宣言の関数型引数が期待型を与えるので、FFIコールバックにも省略が効く。

## Consequences

- 型検査器に「期待型を式へ伝播する」双方向の仕組みが入る。これは配列・structリテラルへの宣言型の伝播(`xs: list<Item> = [Todo{...}]` を通す。前実装で伝播が無く誤診断になった実測あり)と同じ機構なので、実装は一石二鳥になる。
- 仕様5章に省略可能な位置の一覧を明文で書く。
