# ADR-0044: 数字直後の `.` は数値リテラルの小数点に帰属する(`1.abs` はE0106)

- **Status**: accepted
- **Date**: 2026-08-17
- **決定者**: ユーザー + Claude(数値サイクルの字句実装時に確定。本ADRは追録)

## Context(何を決める必要があったか)

字句解析器の数値実装(2026-08-16、PR #24)で「10進整数部の直後の `.` の帰属」を決める必要があった。`1.abs` のような字面は、小数点の読み取り(L-10)とメンバアクセス(X-30)が競合する。決定は仕様1章L-10注(a)として明文化・実装されたが、根拠ADRが存在しなかった。CLAUDE.md正文書ルール(ADRが意思決定の唯一の正)に照らすと宙に浮いた決定であるため、本ADRで追録する。

## Decision(何に決めたか)

1. 10進の整数部を読み終えた直後の `.` は、直後がもう1つの `.`(L-3の `..`)でも数字でもないとき、**小数点の欠落(E0106)** として診断する。spanは数字列+`.` の全体。**`1.abs` はE0106であり、メンバアクセスの `.` とは解釈しない**。
2. この解釈で正当なプログラムは失われない。数値リテラルへのフィールド/メソッドアクセスは3章X-30がstruct型(または組み込み `error`)に限り、プリミティブへのメソッド定義は5章F-8がE0505で禁止するため。
3. 空白・括弧を挟んだ形(`1 .abs`・`(1).abs`)は字句を通し、X-30が型検査で拒否する(字句と型検査の責務分離)。
4. 基数リテラル(`0xFF`)と完成したfloat(`1.5`・`1e6`)の直後の `.` はこの形の対象外である。直後が数字なら(b)の形(整数部の欠落)としてE0106(`3.14.5`)、それ以外は通常の `Dot` として読みX-30が拒否する(`0xFF.abs` は `Int` `Dot` `Ident` に割れる)。

## 検討した代替案と捨てた理由

- **Rust方式(数字を先に確定させて `1` `.` `abs` に割る)**: `1.abs()` をメソッド呼び出しとして型検査に流す方式。Rustは `i32` 等のプリミティブにメソッドが生えるため成立する。MeshはF-8がプリミティブへのメソッドを禁止するため、この方式に利得が無い。
- **Go方式(同じ帰属・専用エラー無し)**: 帰属は同じだが、Goは `1.abs` を `1.` をfloatとして読み切った上での構文エラー(`expected ';', found abs`)にする。MeshはE0106として専用エラーにし、`(1).abs` 形への修正候補を提示する点が異なる(エラーメッセージ品質最優先の方針)。
- 実測(2026-08-16): Go `1.abs` → `expected ';', found abs` / Rust `1.abs()` → E0689(数値リテラルにメソッドは無い)。

## Assumptions(この決定が依存している前提)

- A-22: プリミティブ型へのメソッド禁止(5章F-8・E0505)が維持される。11章の明示変換(`toInt` 等)の設計時に再検査する。

## 既存ADRとの相互作用(2026-08-14監査の教訓により必須)

- **ADR-0030(数値リテラルはフルセット)**: 桁区切り・指数・基数を含む数値構文の採用が、`.` の帰属問題を生む前提。矛盾なし。
- **ADR-0019(範囲 `0..n`)**: `..` の消極規則(L-3)と本決定(L-10注(a))の協働で `0..10` は `Int` `DotDot` `Int` に割れる(E0106にならない)。既存テストが固定済み。
- **ADR-0043(先頭ゼロ全形拒否)**: 検査順はE0106がE0113より先(`0755.` はE0106)。ADR-0043の相互作用節に明記済み。
- **3章X-30・5章F-8**: 本決定の正当性根拠(失われる正当なプログラムが無い)。字句は `.` の解釈のみを決め、型検査には関与しない。

## Consequences(この決定の帰結・影響)

- 仕様1章L-10注(a)に本ADRへの参照を追記する。
- エラーメッセージ層は `1.abs` 形に `(1).abs` への誘導を出す(L-10注(a)の既定。変種文言はroadmapのエラーメッセージ層タスク参照)。
- 11章の明示変換設計時にA-22を再検査する。明示変換をメソッド構文(`1.toInt()` 等)で書く仕様を採る場合は、本決定を見直す新ADRが必要になる(数値リテラル直後の `.` が正当なメンバアクセスとなる)。
- 字句実装は完了済み(PR #24。`float-dot-edge` 等の負例テストが網)。
