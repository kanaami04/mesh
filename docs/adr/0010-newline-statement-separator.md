# ADR-0010: セミコロン無し・改行区切り

- **Status**: accepted
- **Date**: 2026-08-13
- **決定者**: ユーザー + Claude

## Context

Phase 1ラウンド2のQ8。文の区切り記号を決める必要があった。可読性研究(Buse & Weimer)では「括弧・句読点の量」が可読性を下げる主要因子とされている。

## Decision

文はセミコロン無しの**改行区切り**とする(Go/Swift流)。行をまたぐ式は「行末が演算子・カンマ・開き括弧なら継続」の規則で判定する。

## 検討した代替案と捨てた理由

- **セミコロン必須(TS/Rust風)**: 文末が完全に明示的でパーサ実装は楽だが、記号ノイズが全行に乗る。
- **JS流のASI(自動セミコロン挿入)**: 「基本不要だが罠がある」という最悪の中間。採らない。

## Assumptions

- A-9: 改行区切りの継続規則を、例外リスト無しの単純な字句規則として定義しきれる(Goのセミコロン自動挿入規則と同水準)。

## Consequences

- 字句解析器が「行末に文終端を挿入するか」を判定する(Go方式)。仕様1章にその規則を明文で書く。
- fmtが改行位置を統一するため、継続規則の曖昧さは実用上fmtで吸収される。
