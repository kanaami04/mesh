# ADR-0024: コメントは `//` のみ、命名はcamelCase/PascalCase

- **Status**: accepted
- **Date**: 2026-08-14
- **決定者**: ユーザー + Claude

## Context

Phase 1ラウンド5のQ20。コメント記法と命名規約を決める必要があった。

## Decision

- コメントは行コメント `//` のみ。ドキュメンテーションコメント `///` を将来のdocツール用に予約する。ブロックコメント `/* */` は置かない(ネスト問題を避け、字句解析とfmtを単純に保つ)。
- 命名: 変数・関数・フィールド=camelCase、型(struct/type)=PascalCase、パッケージ=小文字単語。**fmt/lintで強制**する(規約ではなく機械が守らせる)。

## 検討した代替案と捨てた理由

- **snake_case**: アイトラッキング研究(Sharif & Maletic 2010)ではcamelCaseより認識が速いという結果がある。しかしJS/TSエコシステム(FFI境界で触れる名前)とAI学習データの主流はcamelCaseで、境界での命名混在のコストが研究上の差分を上回ると判断した。この判断は白紙AI実験(Phase 9)で見直し可能。
- **ブロックコメントも置く**: 一時的なコード無効化には便利だが、その用途はエディタの行コメント一括トグルで足りる。

## Consequences

- 字句仕様(1章)がコメント1種で済む。
- lintの命名検査はエラーメッセージに修正候補(正しいケースの名前)を添える。
