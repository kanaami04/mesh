# drift検査スキル

ドキュメントdriftの検査を実行する:

1. docs/adr/ の全ADR(Status: superseded を除く)を読む。
2. docs/spec/・CLAUDE.md・docs/vision.md・docs/roadmap.md を読み比べ、以下を検出する:
   - ADRの決定と矛盾する記述
   - 覆されたはずの決定が残っている箇所
   - ADR化されていない暗黙の決定(文書に「決定済み」の顔で書かれているが根拠ADRが無いもの)
   - docs/adr/ASSUMPTIONS.md の検証状況が現状と食い違っている行
   - **docs/adr/DEFERRED.md(申し送り台帳)の全行**——トリガーが `phase:`/`layer:` の行は機械が撃たないため、ここが唯一の読む機会。次の4点を見る:
     - (a) **これから入るフェーズ**をトリガーに持つ行(`phase:<次の番号>`)。このスキルはフェーズ**完了時**に走るので、「次に入るフェーズ」を報告することで、着手の直前という正しいタイミングで読まれる。「すでに通過したか」だけを見ると、`phase:9` の行が Phase 9 の**完了後**に初めて出ることになり、「Phase 9で観測してから決める」という中身が手遅れになる(2026-08-20のimpl-reviewで検出)
     - (b) トリガー条件をすでに通過している行(**期限超過**として報告)
     - (c) 対応済みなのに状態が「未対応」のまま残っていないか
     - (d) 台帳が機械可読な書式を保っているか(ID欄が `D-<数字>` で始まる・トリガー欄が `file:`/`phase:`/`layer:` のいずれか)。崩れるとPreToolUseフックが無音で撃たなくなる
3. 指摘ごとに「場所・矛盾の内容・修正案」を報告する。問題がなければ「driftなし」と報告する。
4. 修正はユーザーの承認を得てから行う(勝手に直さない)。
